Slaughterhouse Optimization

Paula Operations Manual

Cairo 3A · Module 4 — the dual-mode optimization engine that decides how many birds of which weight to slaughter to maximise profit. The cockpit is where you configure and launch optimization runs, read each run's harvest and cutting plan in depth, check the market forecast the engine plans against, and score how the forecast models performed — all behind a single sign-in.

  • 6 screens + sign-in
  • Desktop ≥ 1280 px
  • EGP · kg · tonnes

Tip: hover a numbered marker on a screenshot to highlight the matching callout. Click any screenshot to zoom — long pages scroll inside the zoom view.

Since the last manual

What's new in this release

The app has grown substantially since June. If you knew the old three-screen cockpit, here is what changed.

  1. The Dashboard split in two. The old home page tried to be both a launcher and a results viewer. Now Planning (the home page) only configures and launches runs, and every run gets its own Run Results page. Pressing Run Optimization takes you straight to the new run's page, where you watch it execute and the results land in place.
  2. New Run History screen. A full, searchable archive of every run — filter by date, mode, status, or a word from the run's note, then open or permanently delete any run.
  3. Run results are now seven tabs deep. Supply, Demand (demand runs), Production, Allocation, What if, Matrix, and Per-day — with a shared Mix / Fresh / Frozen scope filter, Excel exports (full plan + a step-by-step audit trail), and a per-run constraints record in the header.
  4. Demand mode moved into the Planning form. The separate Demand Override page is retired. On a Demand run you attach an Excel demand workbook — or use the model's own forecast, previewed and confirmed before the run — right in the run form.
  5. Per-run constraints and category picker. Override constraints or restrict which product categories a run may produce — for that run only, never written back to configuration.
  6. New Evaluation screen. Scores the forecast models against what actually happened: price-factor accuracy, demand-forecast accuracy, and the bird-weight curve vs the plant's own recorded weights.
  7. Market Intelligence rebuilt, fresh-only. Two tabs — Price Factor and Demand Forecast — covering fresh products only. The old Weight Distribution view moved: its validation now lives on Evaluation, and each run's weight curve on the run's Supply tab.
  8. Runs outlive the page. A floating progress pill follows you on every screen while a run executes, and a notification bell in the sidebar records finished runs — with desktop notifications if you allow them.
  9. No more API key entry. The backend key is baked into the deployment. Sign in and every screen just works; Settings is now purely a read-only reference of the engine's configuration.
  10. Money discipline. Run results deliberately show no EGP figures — economics appear as price factors, cost factors, and profit / contribution indices, and even the fixed-cost alert states a coverage percentage only.
Getting in

Sign In

Paula is access-controlled. Enter the shared operator credentials to open the cockpit. The session lives in the browser tab — a refresh keeps you signed in, a new tab asks again.

1
2
3
4
  1. Brand panel The Paula "Smart Optimize Hub" mark — confirms you're on the right cockpit.
  2. Username The shared operator credential supplied by the Datalentech team — there are no per-user accounts.
  3. Password Use the eye icon to reveal what you typed. Wrong credentials show an inline error that clears as soon as you edit either field.
  4. Sign in Stays disabled until both fields are filled. Opens the Planning page; Log out sits at the bottom of the app sidebar and acts immediately.

No API key needed — the backend key is built into the deployment. Once signed in, every screen loads live data.

Page 1

Planning

The home page. Configure the next optimization run — mode, period, prices, demand data, per-run constraints and categories — then press Run Optimization. Results never render here: you're taken straight to the new run's own page. The newest 7 runs sit below so the landing page is never empty.

  1. Run type Production maximises profit from available supply; Demand plans against attached demand orders. Your last-used mode is remembered.
  2. Period Opens a booking-style two-month calendar. Pick start and end in two clicks; the past is fully open (historical runs are first-class) and the end date can reach at most one month ahead.
  3. Prices & farm stock Model (forecast) or Actual market prices. With Actual, a Farm stock toggle appears — With sales / Without sales — choosing which historical stock the supply figures count.
  4. Demand data (Demand mode) Attach an .xlsx demand workbook (template download available) or switch to the Model forecast — which must be previewed and ticked "I've reviewed the forecast preview" before the run can start.

  6. Readiness line & Run Optimization The footer always states exactly what will run — or the one thing still blocking it. The red button fires the run and takes you to its results page.
  7. Recent runs The newest 7 runs with date, mode, status badge and note — click any row to open it. "See all runs" opens the full Run History. Deliberately no profit column.

The form is a draft that survives navigation — mode, period, prices, attached demand set, note, constraint and category changes are all still there when you come back. While a run is in flight, a banner with live progress appears here, and a floating pill follows you on every screen.

Page 3

Run Results

Every run has its own results page — reached by starting a run, clicking a history row, or a shared link. While the run executes you watch it here; when it lands, the results render across seven tabs. The tab, scope and selections live in the page address, so a shared link reproduces exactly what you see. Money never appears on this page — economics are factors and indices.

Page 4

Market Intelligence

The forecast model's forward view of the market — for fresh products only. Two tabs: predicted price factors (or EGP/kg selling prices) per SKU, and the model's weekly demand forecast in tonnes per category. Strictly forecast-only: realized actuals and accuracy live on the Evaluation screen.

Price Factor tab

1
2
3
4
5
6
  1. Range controls Start date, horizon (1–120 days), group-by (Whole vs cuts / Product) and metric (Price factor / Price per kg). Nothing reloads until you press "Load range" — the loaded range is written into the address, so links are shareable.
  2. KPI row SKUs in view · Avg price factor (×) · Horizon trend (first → last day) · Model coverage — the share of forecasts routed via the LightGBM model rather than a lookup fallback.
  3. Live bird price The farm-gate input every price factor multiplies. Headline midpoint, low–high range, horizon delta, and a band chart of the uncertainty across the range.
  4. Price factor by category One line per category group; check groups in the rail to drill into individual SKUs ("← All categories" goes back). A factor of 2.40 = predicted to sell at 2.4× the live-bird price.
  5. Categories rail The drill-down control — checking groups switches the chart, KPIs and grid to the SKUs inside them.
  6. Price grid + CSV The full series × date matrix, heat-shaded, with frozen header and first column. CSV always exports per-SKU, per-day values, whatever the on-screen grouping. "—" means no prediction, not zero.

Demand Forecast tab

1

Page 5

Evaluation

How the forecast models performed against realized actuals. Three tabs, each scoring one model: price-factor accuracy, demand-forecast accuracy, and the predicted bird-weight curve vs the plant's own recorded weights. Use it to judge which categories the models get wrong, in which direction, and whether the errors are worsening.

Factor Validation tab

1
2
3
4
  1. Prediction month Step months with ◀ / ▶ (back to January 2025, forward to the current month). The current month scores partial actuals up to today.
  2. Accuracy KPIs Overall weighted MAPE (lower is better), scored coverage, categories scored, rows scored — fresh categories only, with the predicted window and actuals reach stated beneath.
  3. MAPE by category Horizontal bars, worst at the bottom. Green ≤ 8%, amber 8–15%, red above 15%, with dashed threshold lines.
  4. Category table + CSV Every scored category, sortable and searchable. A "Low sample" badge (fewer than 5 rows) mutes the value — noise, not a regression. CSV always exports all categories.

Demand Accuracy tab

1
2
3
4
  1. Scored month The tab finds the latest month that can actually be scored on its own — stepping back automatically until the scoring service accepts one. Scoring covers whole Saturday-ending weeks.
  2. Accuracy & bias KPIs Company MAPE (the Total Fresh rollup), category mean MAPE, signed bias — over- or under-forecasting — and the scored window.
  3. MAPE by category Same shape as the factor chart, looser bands: amber from 8%, red only above 25%. Hover a bar for its signed bias and row count.
  4. Week-type split & scope Accuracy split by the kind of week being predicted, plus a scope footnote naming the target, window and top categories — so the numbers are interpretable.

Weight Distribution tab

1
2
3
4
5
6
7
  1. Window & location Pick a window (up to 92 days; defaults to the last 60) and a location — All locations, Wahat, Regwa, or External. The screenshot scores 1 April – 1 June 2026, pooled across all locations.
  2. Validate range Loads the scoring for the chosen window. Long windows are slow — the service reads the plant's whole Meyn history day by day, so a two-month range can take up to half a minute, and the very first call of the day can time out while the service wakes. If it does, press Validate range again.
  3. Shape-error KPIs Birds in the wrong bucket — the median day's total gap between the two curves, lower is better. Spread gap (CV) — whether the seeded shape is wider (+) or tighter (−) than reality. Grade-A supply bias — what that shape error costs in Grade-A supply. Days scored, with the birds recorded behind it.
  4. Recorded vs predicted weight curve The plant's own Meyn histogram (solid) against the seeded shape the engine predicted (dashed), bird-weighted across the window so a heavy day counts for more than a thin one. The x-axis is dressed weight in kg; the y-axis is each bucket's share of birds.
  5. Where the gap sits The same comparison as a per-bucket difference, in percentage points. Bars above the line are buckets the seed over-fills; below the line, under-fills. The subtitle names the single worst bucket.
  6. Spread over time Each scored day's recorded CV against the seeded one. The seeded line is flat because the engine rescales at constant CV — so a recorded line drifting away from it is the reference shape going stale and due a reseed.
  7. Method footnote Always explains what is measured: both curves sit on the same 33-bucket dressed-weight grid, only shape error is scored, and it counts the days skipped for having no recorded history — the plant does not run every calendar day.

This tab scores shape error only — drift of the average weight itself belongs to the weight & stock forecast, as the on-screen method footnote says. A window where no day has a recorded Meyn histogram shows an empty state rather than inventing a score; try an earlier or wider window.

Page 6

Settings

A read-only reference for the optimization engine's configuration — every parameter it runs with, grouped by namespace, and the active cutting recipes. Nothing here can change anything: editing, version history and rollback are a later phase. There is no API key to manage any more — access is built into the deployment.

1
2
3
4
  1. Configuration The engine's parameters, one namespace at a time — each key with its type, current value, default, and allowed range. An amber "Modified" badge marks values changed from their default (hover it for the default and who last changed it).
  2. Filter & CSV Filter keys by name or description; CSV downloads the whole selected namespace (the filter never narrows the export).
  3. View JSON JSON-typed parameters expand into a readable Fields view (or Raw, with a copy button) instead of an inline value.
  4. Cutting Options The active cutting recipes, one card per option — cuts, yields (shown as % of live weight, matching the Yield column on run tables), weight ranges in grams, and allowed grades. Loads when you first expand the section.

What you see is cached in the browser for about 5 minutes — a value changed on the backend can take up to 5 minutes, or a page reload, to appear.

Day in the life

A typical day with Paula

A common morning routine takes 10–15 minutes.

  1. Sign in — open Paula and enter the operator credentials. You land on Planning.
  2. Configure the run — pick Production or Demand, set the period on the calendar, choose Model or Actual prices. On a Demand run, attach the demand workbook (or use the model forecast and tick the preview confirmation).
  3. Optional per-run tweaks — open Constraints to override a limit for this run only, or Categories to restrict what the run may produce. Both are discarded after the run.
  4. Press Run Optimization — you're taken to the run's own page. Runs take minutes; the floating pill follows you if you navigate away, and the bell records the result.
  5. Read the results tab by tab — Supply (what was harvested), Production (what was made, per category, with its economics), Allocation (output by weight band), What if (how the chosen plan compares to every alternative), Matrix (day × category), Per-day (the day ledger; drill into any day). On a Demand run, the Demand tab shows exactly what was served.
  6. Watch the alerts — a red "Period below fixed cost" banner, red-tinted breach days, or "Cap-limited" badges tell you where the plan is strained.
  7. Export and share — "Export full plan" (Excel) for the packing floor and freezer teams; "Audit trail" when someone asks why the optimizer chose what it chose.
  8. Sanity-check the market — open Market Intelligence for the predicted price factors, live-bird band, and the 4-week demand forecast.
  9. Periodically, check Evaluation — confirm the forecast models still deserve trust: factor MAPE, demand MAPE and bias, and the weight-curve fit.

Runs keep going if you close the page — reopen them from Run History or the notification bell. Loading can be slow on a cold start (up to ~30 seconds); a view that spins for a while and then recovers on its own is normal.

Reference

Glossary

EGP
Egyptian pound. Appears on Market Intelligence (prices) — run results deliberately show no money at all.
Horizon
The planning window an optimization run covers — a range of working days.
Production mode
Default run type — the engine maximises profit from available supply, with no demand orders.
Demand mode
Run type that plans against a demand set — an uploaded workbook, the model forecast, or API-supplied orders.
Demand set
The per-day, per-category orders a demand run serves. Saved with the run — the run page always shows the run's own set, never the live forecast.
Light / Heavy bird
The two flock weight classes. Their split per day shows on the run's Supply and Per-day tabs.
Fresh
Product sold in the production month, not frozen.
Frozen
Product moved to cold storage — made in one month, delivered across the next. Frozen orders are owed by the month, not by any single day.
Strategy
How a day's output splits across fresh and frozen: All Fresh, All Frozen, or Mixed.
Temperature scope
The Mix | Fresh | Frozen filter on the run page's Production, Allocation, What if and Matrix tabs. While narrowed, figures are not run totals — a ribbon says so.
Dressed weight
A bird's weight after processing ≈ live weight × 0.73 (the plant's standing loss factor). Weight bands and distributions are in dressed grams.
Weight band
A dressed-weight range (e.g. 1,200–1,300 g) that output is allocated into — the grain of the Allocation tab.
Loss factor
Per-farm monthly rate of executed rejects plus mortality over total harvested — shown on the Supply tab.
Cutting option
A cutting recipe the engine can apply (e.g. Chest Deboning, Whole Chicken), defining how a carcass splits into products. Recipes are listed in Settings.
Packing
Whole-bird packing as a producer, allocated per weight band. Packing-only categories can never be deselected from a run.
Byproduct
A category that falls out of the cut regardless (e.g. offal) — deselecting it changes nothing, and uploaded byproduct demand is ignored.
Price factor
A category or SKU's predicted selling price as a multiple of the live-bird price — 2.40 means 2.4× the live-bird price that day.
Cost factor
The cost side expressed the same way. Price factor minus cost factor is the margin per unit — the profit index.
Profit index
Price factor minus cost factor — dimensionless margin, comparable across categories.
Contribution index
The optimizer's ranking measure for a cutting option — how much a tonne through that option contributes. What-if rankings sort by it, not by output.
What-if scenario
A counterfactual: how every catalogue option would perform if the whole horizon (or one day) had run it — under Mixed, All Fresh, or All Frozen. The only actual tonnes on that tab are in "Chosen plan".
Fixed cost (FC)
The cost threshold the period must cover. The run page reports coverage as a percentage only — no EGP figure is shown.
Viability
A day's status against fixed cost on the Per-day tab; breached days tint red.
Cap-limited
A day or option clipped by a maximum constraint. A warning, not an error — exceeded soft caps are supported outcomes.
Constraint
A limit the optimizer must respect (birds, kg, or percentage; hard or soft; per day or per period). Durable constraints live in configuration; per-run overrides in the Planning form.
Degraded
A run recorded as completed whose result carries a caveat — shown amber in run lists; the "Completed" filter includes it.
Live bird price
The modelled farm-gate price per kg of live chicken that every price factor multiplies.
Model coverage
On Market Intelligence: the share of forecasts routed via the LightGBM model rather than a lookup fallback.
MAPE
Mean absolute percentage error — the Evaluation screen's headline accuracy measure. Lower is better.
Bias
The signed direction of forecast error — positive is over-forecasting, negative under-forecasting.
CV
Coefficient of variation — a unitless measure of how spread out the flock's weights are.
Namespace
A group of related engine parameters on the Settings page (e.g. capacity, calendar, costs).
